## ⬡ Firmware del Nodo de Borde (ESP32)

**Herramientas:** Core ESP32, `PubSubClient` (MQTT), `WiFi`, `DHT`, `Wire`.

### El Superloop Concurrente

El firmware usa `millis()` en lugar de `delay()` para que la recolección de sensores, el servidor WLAN local y el envío MQTT convivan sin bloqueos.

```cpp
void loop() {
  unsigned long ahora = millis();

  // 1. Adquisición periódica de sensores (no bloqueante)
  if (ahora - tUltimaLectura >= INTERVALO_LECTURA) {
    tUltimaLectura = ahora;
    leerSensores();          // DHT, BMP180, LDR + distancia por ISR
    calcularFusion();        // Índice de Riesgo 80/20
    actualizarAlarmas();     // Máquina de estados de alarmas
  }

  // 2. Atención del servidor web local (redundancia in-situ)
  servidorWeb.handleClient();

  // 3. Telemetría MQTT (publish/subscribe)
  if (ahora - tUltimoEnvio >= INTERVALO_MQTT) {
    tUltimoEnvio = ahora;
    publicarTelemetria();    // wms/sabana/nodo1/telemetria
  }
  mqtt.loop();               // procesa mensajes entrantes (ACK remoto)
}
```

### Manejo de Errores (Tolerancia a Fallos)

<Warning>
Si un sensor climático devuelve `NaN`, el sistema **no se detiene**: el nivel de agua sigue reportándose y el nodo transiciona a `ESTADO_FALLA`, señalando datos ambientales no confiables sin perder la medición crítica de nivel.
</Warning>

## ▸ Arquitectura de Red y Telemetría

### Gateway Local (Raspberry Pi)

La Raspberry Pi ejecuta **Mosquitto** como broker MQTT local y un script (Python / Node) que **suscribe** la telemetría, la guarda en **SQLite** para persistencia y luego hace de **bridge** reenviando los datos hacia **Ubidots**. Así, aun sin Internet, los datos quedan almacenados localmente y se sincronizan al recuperar la conexión.

### Diccionario de Tópicos MQTT

| Tópico | Dirección | Propósito |
| --- | --- | --- |
| `wms/sabana/nodo1/telemetria` | ESP32 **publica** | Payload JSON con todas las variables medidas |
| `wms/sabana/nodo1/alarmas/estado` | ESP32 **publica** | Cambio de estado crítico de la alarma |
| `wms/sabana/nodo1/alarmas/ack` | ESP32 **suscribe** | Recibe la orden de silencio remoto (ACK) |

### Estructura del Payload (JSON)

```json
{
  "nodo": "nodo1",
  "nivel": 72.4,
  "riesgo": 0.68,
  "luz": 845,
  "temp": 24.3,
  "humedad": 58.1,
  "presion": 1012.5,
  "estado": "PREVENTIVA",
  "ts": 1730563200
}
```

<Note>
El payload se mantiene liviano (JSON plano) para minimizar el ancho de banda y la carga de parseo en el gateway.
</Note>
