**El Fenómeno de El Niño 2026 amenaza el suministro hídrico de la Sabana Centro.** WMS responde con telemetría distribuida, fusión sensorial e inteligencia artificial para anticipar el estrés hídrico antes de que sea irreversible.

---

## ⬡ ¿Qué es WMS?

El [Fenómeno de El Niño 2026](https://www.ideam.gov.co) ha intensificado la presión sobre las fuentes hídricas de la **Sabana Centro de Cundinamarca**. Según el IDEAM [1] y la CAR Cundinamarca [2], **20 municipios de la región se encuentran en riesgo extremo** de desabastecimiento hídrico, con **16 escenarios críticos** identificados en el más reciente plan de contingencia regional \[3\][4]. El suministro de más de 400 000 habitantes depende de reservorios superficiales con escasa instrumentación, y esta brecha de observación es el principal obstáculo para la gestión preventiva del recurso.

**WMS cierra esa brecha** con una red de nodos embebidos de bajo costo capaces de adquirir, fusionar y transmitir variables hidrometeorológicas críticas en tiempo casi real, sin depender de infraestructura costosa ni conectividad permanente.

El sistema combina una **arquitectura dual borde/nube**: el nodo ESP32 ejecuta **adquisición concurrente no bloqueante mediante rutinas de interrupción (ISR)** — medición de nivel hídrico por HC-SR04, temperatura/humedad por DHT11, presión atmosférica por BMP180 y radiación solar relativa por LDR — sirviendo además un tablero local por WLAN antes de publicar por MQTT. El gateway Raspberry Pi concentra la telemetría en un broker [Mosquitto](https://mosquitto.org), la persiste en SQLite y la reenvía a [Ubidots](https://ubidots.com) como plataforma cloud; los actuadores locales (LCD, LED RGB y buzzer) notifican al operador in situ, y el apagado de alarma se ejecuta mediante comando ACK autenticado vía tópico MQTT restringido.

Sobre esa base, WMS implementa una **arquitectura híbrida de inferencia en la nube**: el gateway orquesta consultas a la [API de Gemini](https://ai.google.dev) para análisis predictivo y soporte de racionamiento, transformando datos crudos del terreno en recomendaciones accionables. El modelo de lenguaje corre en servidores de Google; la lógica de orquestación, los prompts y la persistencia de resultados residen en el gateway local.

<Tabs>
  <Tab title="Sensórica">
    | Variable | Sensor | Bus / Interfaz |
    | --- | --- | --- |
    | Nivel de agua | HC-SR04 (ultrasónico) | GPIO — trigger/echo + ISR de eco |
    | Temperatura / Humedad | DHT11 | Single-bus (OneWire) |
    | Presión atmosférica | BMP180 | I²C (SDA/SCL) |
    | Radiación solar relativa | LDR (fotorresistencia) | ADC 12 bits (GPIO34) |
    | Evaporación potencial | Variable derivada — calculada en gateway | Método Hargreaves (T + Rad_LDR) |
  </Tab>
  <Tab title="Cómputo y Red">
    | Componente | Detalle |
    | --- | --- |
    | Nodo embebido | ESP32 · Superloop no bloqueante + ISRs · servidor HTTP local |
    | Gateway local | Raspberry Pi 4 · Mosquitto broker · SQLite |
    | Protocolo campo → gateway | MQTT bidireccional (TCP/IP · WLAN) |
    | Protocolo gateway → nube | MQTT → [Ubidots](https://ubidots.com) (token auth) |
    | Latencia borde → gateway | \< 2 s |
    | Latencia gateway → nube | \< 10 s |
    | Redundancia | SQLite local + reenvío automático en reconexión |
  </Tab>
  <Tab title="Seguridad">
    | Capa | Mecanismo |
    | --- | --- |
    | Tablero local (ESP32) | HTTP Basic Auth sobre servidor embebido |
    | Gateway (Mosquitto) | Usuario + contraseña · ACL por tópico |
    | Tablero global (Ubidots) | API Token + RBAC por dashboard |
    | Actuadores remotos | Comando ACK autenticado vía tópico MQTT restringido |
  </Tab>
  <Tab title="IA y Actuación">
    | Función | Implementación |
    | --- | --- |
    | Modelo de IA | [Gemini API](https://ai.google.dev) — inferencia en nube |
    | Orquestación | Gateway RPi · Python · prompts auditables |
    | Análisis | Detección de anomalías · soporte de racionamiento |
    | Actuadores in situ | LCD · LED RGB · buzzer |
    | Control remoto | ACK/SILENCE autenticado vía tópico MQTT restringido |
  </Tab>
</Tabs>
